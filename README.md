# Учебная виртуальная машина. Вариант 5

Ассемблер на Python 3.10+ переводит текст программы в машинный код.
Используется стандартная библиотека Python.

## Язык ассемблера

Одна команда на строку. Мнемоники регистронезависимы. Аргумент отделяется
пробелом или табуляцией. Пустые строки и комментарии после `;` игнорируются.

| Мнемоника | Аргумент | Действие |
| --- | --- | --- |
| `LOAD n` | Десятичное целое от −65536 до 65535 | Записать константу в аккумулятор |
| `READ d` | Смещение от 0 до 1023 | Загрузить в аккумулятор значение из памяти по адресу `ACC + d` |
| `WRITE a` | Адрес от 0 до 8191 | Записать аккумулятор в ячейку `a` |
| `ABS` | Без аргументов | Загрузить в аккумулятор модуль числа из ячейки с адресом `ACC` |

Для представления отрицательных констант поле B у `LOAD` трактуется
как 17-битное целое в дополнительном коде.

## Запуск

```sh
./run.sh assemble examples/spec.asm spec.bin --test
./run.sh test
```

Ассемблер принимает путь к исходнику, путь к выходному файлу и флаг `--test`.
Ассемблер записывает двоичный файл и выводит его размер. С флагом
`--test` он также печатает байты каждой команды в порядке их записи.

```text
0xFF, 0xCC, 0x01
0x38, 0x13, 0x01
0x18, 0x9E, 0x01
0x33
Размер двоичного файла: 10 байт
```

В первом коммите режим тестирования выводил промежуточное представление:

```text
A=127, B=921
A=56, B=550
A=24, B=828
A=51
```

## Интерпретатор и копирование массива

```sh
mkdir -p out
./run.sh assemble examples/copy.asm out/copy.bin
./run.sh interpret out/copy.bin out/copy.json 200 202
cat out/copy.json
```

Интерпретатор принимает путь к машинному коду, путь к JSON-дампу и два
десятичных адреса. Обе границы диапазона включаются. Ключи объекта JSON
соответствуют адресам, значения — целым числам в ячейках. В приведённом
примере ячейки 200–202 получают значения 9, −4 и 12.

Память данных содержит 8192 ячейки с адресами от 0 до 8191. Память и
аккумулятор новой машины заполнены нулями. Код читается из отдельного
массива байтов. Выполнение заканчивается в конце программы.

## Проверка ABS

```sh
./run.sh assemble examples/abs.asm out/abs.bin
./run.sh interpret out/abs.bin out/abs.json 30 31
cat out/abs.json
```

Программа записывает −65536 по адресу 30, вычисляет его модуль и
сохраняет 65536 по адресу 31. Ячейки и аккумулятор хранят целые числа
Python, поэтому результат не ограничен шириной поля константы.

## Тестовая задача с вектором длины 7

Входной вектор хранится по адресам 100–106. Для каждого элемента команда
`LOAD` помещает адрес в аккумулятор, `ABS` читает число по этому адресу,
а `WRITE` сохраняет его модуль в новый вектор по адресам 200–206.

```sh
mkdir -p out
for name in mixed negative boundary; do
    ./run.sh assemble "examples/vector_$name.asm" "out/$name.bin"
    ./run.sh interpret "out/$name.bin" "out/$name.json" 200 206
    cat "out/$name.json"
done
```

| Пример | Ячейки 100–106 | Ячейки 200–206 по JSON-дампу |
| --- | --- | --- |
| `vector_mixed.asm` | −8, 0, 3, −21, 7, −1, 12 | 8, 0, 3, 21, 7, 1, 12 |
| `vector_negative.asm` | −2, −4, −6, −8, −10, −12, −14 | 2, 4, 6, 8, 10, 12, 14 |
| `vector_boundary.asm` | −65536, 65535, −32768, 0, 1, −1, −65535 | 65536, 65535, 32768, 0, 1, 1, 65535 |

## Формат кода и устройство проекта

Поле A занимает младшие 7 бит. Поле B, если оно есть, начинается с бита 7.
Многобайтовые команды записываются младшим байтом вперёд. Зарезервированные
старшие биты равны нулю. Смещение `READ` и адрес `WRITE` беззнаковые.

| Команда | Поле A | Поле B (номера битов) | Размер, байт |
| --- | --- | --- | --- |
| `LOAD` | 127 | 7–23 | 3 |
| `READ` | 56 | 7–16 | 3 |
| `WRITE` | 24 | 7–19 | 3 |
| `ABS` | 51 | отсутствует | 1 |

| Модуль | Функции и назначение |
| --- | --- |
| `src/isa.py` | `operand_bounds` определяет пределы поля, `describe_fields` форматирует поля команды. |
| `src/assembler.py` | `parse_operand` проверяет число, `parse_instruction` разбирает команду. |
| `src/assembler.py` | `parse_program` разбирает файл, `main` создаёт двоичный файл через CLI. |
| `src/codec.py` | `encode_instruction` упаковывает команду, `format_bytes` форматирует её байты. |
| `src/codec.py` | `decode_instruction` читает команду, `decode_operand` восстанавливает её аргумент. |
| `src/vm.py` | `check_address` проверяет адрес, `read` и `write` обращаются к ячейкам данных. |
| `src/vm.py` | `execute` исполняет команду, `run` — программу, `dump` формирует срез памяти. |
| `src/interpreter.py` | `main` запускает машину с нулевым состоянием и записывает JSON. |

Сборку двоичного кода выполняет `./run.sh assemble`. Сам проект запускается
через Python без установки пакетов и отдельной сборки. Команды
`./run.sh assemble --help` и `./run.sh interpret --help` показывают
параметры. При неверных аргументах, ошибках ввода-вывода или выполнении
некорректной команды приложение печатает диагностику в stderr.

## История этапов

1. Разбор текста и вывод полей.
2. Формирование машинного кода.
3. Декодирование, память и копирование массива.
4. Выполнение `ABS`.
5. Три примера с векторами и сквозные тесты.

История доступна через `git log --reverse --oneline`. Для проверки вывода
полей первого этапа можно создать отдельное рабочее дерево:

```sh
git worktree add --detach ../variant5-stage1 "$(git rev-list --max-parents=0 HEAD)"
(cd ../variant5-stage1 && ./run.sh assemble examples/spec.asm spec.bin --test)
git worktree remove ../variant5-stage1
```
